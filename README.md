# Claude Web Chat

Локальный веб-интерфейс для общения с моделями Claude через Anthropic Messages API или совместимый API-прокси.

Приложение написано на Python и Streamlit. Оно поддерживает несколько чатов, потоковую генерацию ответов, загрузку текстовых файлов проекта в контекст и автоматическое сохранение истории в SQLite.

> Приложение рассчитано на локальное однопользовательское использование. Авторизация пользователей и разделение истории между пользователями не реализованы.

## Возможности

- **Несколько чатов:** создание, переключение и удаление.
- **Потоковые ответы:** текст появляется по мере получения от API.
- **История в SQLite:** сообщения сохраняются между запусками приложения.
- **Контекст проекта:** загрузка текстовых файлов для анализа моделью.
- **Отображение кода:** подсветка синтаксиса и отдельные кнопки копирования.
- **Копирование ответа:** копирование всего ответа вместе с Markdown-разметкой.
- **Экспорт чата:** скачивание истории и сведений об ошибках в JSON.
- **Повтор запроса:** повторная отправка сообщения после ошибки.
- **Редактирование сообщения:** изменение последнего сообщения, для которого ещё нет завершённого ответа.
- **Статистика:** отображение количества входных и выходных токенов, если API передал эти сведения.
- **Настраиваемое подключение:** API-ключ, адрес API-сервера, идентификатор модели и лимит ответа.
- **Локальный запуск:** автоматическое открытие приложения в браузере через `launcher.py`.
- **Возможность сборки:** упаковка приложения с помощью PyInstaller.

- Python **3.10 или новее**.
- Доступ к Anthropic API либо совместимому с ним API-прокси.
- API-ключ с доступом к выбранной модели.
- Современный браузер.
- Доступ на запись в каталог базы данных.

> Используемая версия Python также должна поддерживаться установленными версиями зависимостей. В `requirements.txt` версии пакетов не закреплены.

## Установка

### 1. Получите исходный код

Клонируйте репозиторий через Git либо скачайте ZIP-архив со страницы проекта и распакуйте его.

Откройте терминал в корневой папке проекта.

### 2. Создайте виртуальное окружение

**Windows:**

```powershell
py -m venv .venv
```

**Linux / macOS:**

```bash
python3 -m venv .venv
```

### 3. Активируйте окружение

**Windows PowerShell:**

```powershell
.\.venv\Scripts\Activate.ps1
```

**Windows CMD:**

```bat
.venv\Scripts\activate.bat
```

**Linux / macOS:**

```bash
source .venv/bin/activate
```

Если PowerShell блокирует выполнение скриптов, можно использовать CMD или запускать Python напрямую из `.venv`, не активируя окружение.

### 4. Установите зависимости

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## Настройка

Создайте файл `.env` в корне проекта.

Пример настроек для официального Anthropic API:

```dotenv
# Официальный API или совместимый сервер.
ANTHROPIC_BASE_URL=https://api.anthropic.com

# Укажите точный идентификатор модели, доступной вашему аккаунту.
CLAUDE_MODEL=your-model-id

# Пример значения. Проверьте ограничения выбранной модели и провайдера.
CLAUDE_MAX_TOKENS=4096

# Необязательно: ключ можно ввести в интерфейсе.
ANTHROPIC_API_KEY=

# Необязательно: путь к базе истории.
APP_DB_PATH=data/chat_history.sqlite3
```

Перед запуском замените `your-model-id` на действующий идентификатор модели.

### Переменные окружения

| Переменная | Обязательная | Назначение |
|---|---|---|
| `CLAUDE_MODEL` | Да | Идентификатор модели, доступной через выбранный API |
| `CLAUDE_MAX_TOKENS` | Да | Положительное целое число: максимальное количество токенов ответа |
| `ANTHROPIC_API_KEY` | Нет | Начальное значение API-ключа; ключ также можно ввести в боковой панели |
| `ANTHROPIC_BASE_URL` | Нет | Базовый адрес API; если не указан, используется адрес по умолчанию из SDK |
| `APP_DB_PATH` | Нет | Путь к SQLite; по умолчанию `data/chat_history.sqlite3` |

Переменные, уже заданные в окружении процесса, имеют приоритет над значениями из `.env` при стандартной работе `load_dotenv()`.

### Подключение через прокси

В `ANTHROPIC_BASE_URL` укажите базовый адрес совместимого API-сервера согласно документации его оператора.

Для серверов, повторяющих структуру официального Anthropic API, обычно указывается адрес без `/v1/messages`: маршрут запроса добавляет SDK.

Прокси должен поддерживать используемые приложением возможности Anthropic Messages API, включая потоковую передачу ответов.

> API-ключ, сообщения и содержимое загруженных файлов передаются выбранному API-серверу. Используйте только доверенных провайдеров.

### Ограничение длины ответа

Приложение передаёт `CLAUDE_MAX_TOKENS` в параметр `max_tokens` API-запроса.

Собственного дополнительного верхнего предела приложение не устанавливает, однако допустимое значение зависит от модели и API-провайдера.

- Слишком большое значение может привести к ошибке запроса.
- Максимальное количество токенов не гарантирует ответ такой длины.
- Загруженные файлы и история занимают часть контекстного окна модели.
- При завершении с `stop_reason=max_tokens` приложение показывает предупреждение о возможном обрезании ответа.

## Запуск

### Рекомендуемый вариант

Из корня проекта выполните:

```bash
python launcher.py
```

Лаунчер:

1. Устанавливает рабочую папку приложения.
2. Запускает Streamlit на `127.0.0.1:8501`.
3. Проверяет готовность сервера.
4. Открывает приложение в браузере.

Адрес интерфейса:

```text
http://localhost:8501/
```

Не закрывайте терминал во время работы. Для остановки приложения нажмите `Ctrl+C`.

### Запуск напрямую через Streamlit

```bash
python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501 --browser.gatherUsageStats false
```

При таком запуске относительный путь к базе данных разрешается относительно текущей рабочей папки. Поэтому рекомендуется выполнять команду из корня проекта.

## Использование

### Подключение к API

1. Откройте раздел **«Подключение к API»** в боковой панели.
2. Введите API-ключ, если он не был задан через окружение.
3. Отправьте сообщение через поле ввода внизу страницы.

Ключ из интерфейса хранится в текущей сессии и не записывается в историю чатов. Кнопка **«Очистить API-ключ»** очищает его в текущей сессии, но не изменяет `.env` и переменные окружения.

### Работа с чатами

В боковой панели можно:

- создать новый чат;
- переключиться между чатами;
- удалить текущий чат;
- экспортировать выбранный чат в JSON.

Сообщения автоматически сохраняются в SQLite. Если удалить последний чат, приложение создаст новый пустой чат.

### Загрузка контекста проекта

В разделе **«Контекст проекта»** выберите текстовые файлы.

Поддерживаются файлы в кодировке **UTF-8**, в том числе UTF-8 с BOM.

Ограничения загрузки:

| Параметр | Лимит |
|---|---:|
| Количество файлов | 20 |
| Размер одного файла | 512 КиБ |
| Общий размер принятых файлов | 2 МиБ |

Файлы с ошибками кодировки, нулевыми байтами или повторяющимися именами пропускаются с предупреждением.

Особенности контекста:

- контекст общий для всех чатов текущей сессии;
- файлы не сохраняются в SQLite;
- файлы не включаются в экспорт чата;
- текущий набор файлов добавляется к первому сообщению пользователя при формировании каждого API-запроса;
- изменение набора файлов влияет на последующие запросы, в том числе в уже существующих чатах;
- после потери или завершения сессии файлы потребуется загрузить заново.

Кнопка **«Очистить контекст»** удаляет выбранные файлы из текущей сессии.

> Лимиты загрузки измеряются в байтах и не гарантируют, что файлы вместе с историей поместятся в контекстное окно модели.

### Копирование ответов

Для каждого распознанного блока кода отображается отдельная кнопка **«Копировать код»**. Она копирует код без Markdown-ограждений.

Кнопка **«Копировать весь ответ»** копирует исходный текст ответа вместе с Markdown-разметкой.

Если браузер блокирует доступ к буферу обмена, выделите текст и используйте `Ctrl+C` или `Cmd+C`.

### Ошибки и повторная отправка

Если запрос завершился ошибкой, последнее сообщение пользователя остаётся в истории без завершённого ответа.

Можно:

- повторить запрос;
- отредактировать сообщение и затем повторить запрос;
- удалить сообщение.

Если поток оборвался после получения части ответа, незавершённый текст отображается отдельно. Он сохраняется в сведениях об ошибке, но не включается в историю, отправляемую API при повторном запросе.

> Повторный запрос — отдельное обращение к API. Условия оплаты и учёта неуспешных запросов определяются провайдером.

## Хранение данных

По умолчанию история находится в:

```text
data/chat_history.sqlite3
```

Каталог и таблица базы создаются автоматически.

В базе сохраняются:

- названия и идентификаторы чатов;
- сообщения пользователя и завершённые текстовые ответы;
- временные метки;
- идентификатор запрошенной модели;
- причина завершения ответа;
- статистика токенов, если она доступна;
- сведения об ошибках, включая частичный текст оборванного ответа.

Не сохраняются в базе:

- API-ключ из интерфейса;
- загруженные файлы проекта.

При этом ответ модели может содержать фрагменты переданных файлов — такие фрагменты сохраняются как часть ответа.

### Резервное копирование

Для резервной копии всех чатов остановите приложение и скопируйте SQLite-файл в безопасное место.

Экспорт JSON сохраняет только выбранный чат. Импорт JSON через интерфейс в текущей версии не реализован.

## Сборка исполняемого файла

Проект содержит лаунчер с поддержкой путей PyInstaller, включая режим `--onefile`.

Ниже приведены базовые команды сборки. Для конкретных версий Streamlit, PyInstaller и операционной системы могут потребоваться дополнительные настройки.

Собирать приложение рекомендуется в отдельном виртуальном окружении и на той операционной системе, для которой предназначен исполняемый файл.

### Windows

```powershell
python -m PyInstaller --noconfirm --clean --onefile --name ClaudeWebChat --add-data "app.py;." --collect-all streamlit --collect-all anthropic --copy-metadata streamlit --copy-metadata anthropic launcher.py
```

Результат:

```text
dist/ClaudeWebChat.exe
```

### Linux / macOS

```bash
python -m PyInstaller --noconfirm --clean --onefile --name ClaudeWebChat --add-data "app.py:." --collect-all streamlit --collect-all anthropic --copy-metadata streamlit --copy-metadata anthropic launcher.py
```

Результат:

```text
dist/ClaudeWebChat
```

### Настройка собранного приложения

1. Поместите `.env` рядом с исполняемым файлом.
2. Укажите доступную модель и поддерживаемое значение `CLAUDE_MAX_TOKENS`.
3. Запустите приложение.
4. Введите API-ключ в интерфейсе либо задайте его в окружении.

При стандартных настройках папка `data` будет создана рядом с исполняемым файлом. Для этого необходимы права на запись.

Если папка приложения недоступна для записи, задайте `APP_DB_PATH` с путём к доступному каталогу.

> Не включайте личный `.env` или историю переписки в распространяемую сборку. Приведённые команды намеренно не добавляют эти файлы в исполняемый файл.

## Безопасность и приватность

- Не публикуйте API-ключи, пароли, приватные ключи и другую конфиденциальную информацию.
- Не добавляйте `.env` и базу истории в Git.
- История и экспортируемые JSON-файлы не шифруются самим приложением.
- Все пользователи, имеющие доступ к одной базе, используют общую историю: разграничения доступа нет.
- Лаунчер привязывает сервер к `127.0.0.1`. Не открывайте его в публичную сеть без отдельной аутентификации и мер защиты.
- Очищение API-ключа в интерфейсе не удаляет его из `.env`.
- Загруженные файлы передаются API-провайдеру вместе с запросами.
- Инструкция считать содержимое файлов данными помогает снизить риск prompt injection, но не гарантирует защиту от него.
- Если секрет уже попал в публичный репозиторий, удаление файла из последнего коммита недостаточно: отзовите секрет и при необходимости очистите историю Git.

## Устранение неполадок

### Приложение сообщает, что не задан `CLAUDE_MODEL`

Укажите в `.env` точный идентификатор модели, доступной у вашего провайдера.

Идентификаторы моделей зависят от API-сервера. Не следует считать произвольное название гарантированно поддерживаемым.

### Приложение сообщает об ошибке `CLAUDE_MAX_TOKENS`

Переменная обязательна и должна содержать положительное целое число:

```dotenv
CLAUDE_MAX_TOKENS=4096
```

Допустимый верхний предел уточняйте у провайдера.

### Ошибка авторизации

Проверьте:

- корректность API-ключа;
- адрес `ANTHROPIC_BASE_URL`;
- соответствие ключа выбранному провайдеру;
- наличие доступа к API.

### Модель или API-маршрут не найдены

Проверьте `CLAUDE_MODEL` и базовый адрес сервера.

Убедитесь, что сервер поддерживает Anthropic Messages API и выбранную модель.

### API отклоняет запрос

Возможные причины:

- превышен контекст модели;
- запрошен слишком большой `max_tokens`;
- модель не поддерживает параметры запроса;
- у аккаунта нет доступа к модели.

Попробуйте уменьшить `CLAUDE_MAX_TOKENS`, убрать часть файлов или начать новый чат.

### Превышен лимит запросов

Проверьте квоты, баланс и ограничения API-провайдера. Повторите запрос позже.

### Не удаётся сохранить историю

Проверьте:

- значение `APP_DB_PATH`;
- права на запись;
- доступность диска;
- не заблокирована ли база другим процессом.

Если сохранение не удалось, изменения могут оставаться только в текущей сессии до успешной повторной записи.

### Браузер не открылся автоматически

Откройте вручную:

```text
http://localhost:8501/
```

Проверьте сообщения в терминале. Порт `8501` может быть занят другим процессом.

### Загруженный файл отклонён

Убедитесь, что файл:

- сохранён в UTF-8;
- не является бинарным;
- не превышает лимит размера;
- имеет уникальное имя среди принятых файлов.

### `.env` не применяется

При использовании `launcher.py` держите `.env` рядом с исходным лаунчером или исполняемым файлом.

При прямом запуске Streamlit выполняйте команду из корня проекта.

Также проверьте переменные окружения процесса: они могут иметь приоритет над `.env`. После изменения настроек перезапустите приложение.

## Ограничения текущей версии

- Нет регистрации и аутентификации пользователей.
- Нет разделения истории по пользователям.
- Нет синхронизации изменений между несколькими одновременно открытыми сессиями.
- Контекст файлов общий для всех чатов текущей сессии.
- Загруженные файлы не сохраняются между сессиями.
- История передаётся целиком без автоматического сокращения.
- Нет импорта ранее экспортированных чатов.
- Нет интерфейса вызова инструментов, обработки изображений и других нетекстовых ответов.
- Редактировать через интерфейс можно только последнее сообщение без завершённого ответа.
- Разбор Markdown-блоков кода специализированный: сложные вложенные конструкции могут отображаться иначе, чем в полном Markdown-парсере.
- Версии зависимостей не закреплены; обновления пакетов могут потребовать изменений в проекте.
- Работа с конкретным прокси зависит от его совместимости с Anthropic SDK.
